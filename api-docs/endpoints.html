Endpoints

All paths are relative to the API root — {base}/api/ by default. With static_json: true in _meta.json, the client appends .json to the path before the query string.

GET/manga/_catalog

Backs the Home "Browse" row. Returns every title the source knows about, as a collection envelope. A static source should include its full catalog here; a dynamic source can paginate normally.

Query params

None required. A dynamic backend may accept contentRating[], availableTranslatedLanguage[], includedTags[], limit, offset; the client is tolerant of any being ignored.

Response (abbreviated)

{
  "result": "ok",
  "response": "collection",
  "data": [
    {
      "id": "demo-01",
      "type": "manga",
      "attributes": {
        "title": { "en": "Lorem Ipsum Dolor" },
        "altTitles": [ { "es": "Lorem Ipsum Dolor (es)" } ],
        "description": { "en": "Lorem ipsum dolor..." },
        "originalLanguage": "en",
        "status": "ongoing",
        "year": 2024,
        "contentRating": "safe",
        "tags": [ { "id": "11111111-...", "type": "tag",
          "attributes": { "name": {"en": "Action"}, "group": "genre", "version": 1 } } ],
        "availableTranslatedLanguages": ["en", "es"],
        "latestUploadedChapter": "ch-01-b"
      },
      "relationships": [
        { "id": "cover-demo-01", "type": "cover_art",
          "attributes": { "fileName": "https://placehold.co/400x600/.../.png?text=..." } }
      ]
    },
    { "id": "demo-02", "...": "..." }
  ],
  "limit": 30, "offset": 0, "total": 30
}

Fields the app reads

  • id, attributes.title (localized map, falls back to any key), attributes.description.
  • attributes.contentRating — safe | suggestive | erotica | pornographic.
  • attributes.availableTranslatedLanguages — array of IETF tags; used for the language chip filter.
  • attributes.tags[] — each is a tag entity (see /manga/tag).
  • attributes.year, attributes.status, attributes.originalLanguage.
  • relationships[] where type == "cover_art" — the attributes.fileName is used by the Cover Store. If it's an absolute http(s):// URL it's used verbatim; otherwise it's resolved under {coversUrl}/{mangaId}/{fileName}.{size}.jpg (see covers.html).
  • attributes.latestUploadedChapter is read for the "has updates" dot; isLocked, links, state, version are present in the demo but currently ignored by the app.

GET/manga/{id}

Title detail. Same manga entity shape as the catalog, but wrapped in an entity response and (in the demo) with author + artist relationships expanded.

Response (abbreviated)

{
  "result": "ok",
  "response": "entity",
  "data": {
    "id": "demo-01",
    "type": "manga",
    "attributes": { "title": {"en": "Lorem Ipsum Dolor"}, "...": "..." },
    "relationships": [
      { "id": "cover-demo-01", "type": "cover_art",
        "attributes": { "fileName": "https://..." } },
      { "id": "author-demo-01", "type": "author",
        "attributes": { "name": "Alpha Writer" } },
      { "id": "artist-demo-01", "type": "artist",
        "attributes": { "name": "Delta Brush" } }
    ]
  }
}

Author and artist names are shown on the detail screen when present; absent is fine.

GET/manga/{id}/feed

Chapter list for one title. The detail screen pages through this to render the chapter table.

Query params

A dynamic backend may accept translatedLanguage[], order[chapter]=asc|desc, limit, offset. A static source returns all chapters in readableAt desc; the client sorts locally.

Response (abbreviated)

{
  "result": "ok",
  "response": "collection",
  "data": [
    {
      "id": "ch-01-a",
      "type": "chapter",
      "attributes": {
        "volume": "1",
        "chapter": "1",
        "title": "Lorem Primum",
        "translatedLanguage": "en",
        "externalUrl": null,
        "isUnavailable": false,
        "publishAt": "2026-10-24T10:59:00+00:00",
        "readableAt": "2026-10-24T10:59:00+00:00",
        "pages": 3
      },
      "relationships": [
        { "id": "demo-group-1", "type": "scanlation_group",
          "attributes": { "name": "Demo Translators", "focusedLanguages": ["en"] } },
        { "id": "demo-01", "type": "manga" }
      ]
    },
    { "id": "ch-01-b", "...": "..." }
  ],
  "limit": 2, "offset": 0, "total": 2
}

Fields the app reads

  • id, attributes.chapter (string, "1", "2.5", "Oneshot"), attributes.volume, attributes.title.
  • attributes.translatedLanguage — filtered against the user's chip selection.
  • attributes.readableAt — sort key and age label.
  • attributes.pages — shown on the detail row ("3 pages"). 0 paired with a non-null externalUrl renders "Opens on {host}" instead.
  • attributes.externalUrl — when non-null the chapter opens in the in-app WebView; /at-home/server is not called.
  • relationships[] where type == "scanlation_group" — the attributes.name is shown as the uploader label.
  • isUnavailable, publishAt, version, timestamps are present in the demo and currently ignored.

GET/at-home/server/{chapterId}

Page list for one chapter. Returned shape is intentionally thin: a hash and two parallel arrays (full and data-saver). The user's "Image quality" preference picks which array to iterate.

Response

{
  "result": "ok",
  "baseUrl": "",
  "chapter": {
    "hash": "ch-01-a",
    "data": [
      "https://placehold.co/800x1200/222222/eeeeee.png?text=...+Page+1",
      "https://placehold.co/800x1200/222222/eeeeee.png?text=...+Page+2",
      "https://placehold.co/800x1200/222222/eeeeee.png?text=...+Page+3"
    ],
    "dataSaver": [
      "https://placehold.co/800x1200/.../.png?text=...+Page+1",
      "..."
    ]
  }
}

How URLs resolve

  • If data[i] is an absolute http(s):// URL (as in the demo), it is used verbatim.
  • Otherwise the URL is built as {baseUrl}/{quality}/{hash}/{filename}, where quality is data or data-saver.
  • When baseUrl is the empty string, the API URL is substituted — so a static source can host images under {apiUrl}/data/{hash}/… alongside its JSON.

GET/manga

Backs the Home "Popular new titles" row and the Search default list. Shape is identical to /manga/_catalog. A static source can serve the same JSON at both paths (the demo does).

The real contract uses the query string: Popular passes order[followedCount]=desc&createdAtSince=…; Search passes a free-text title= plus the current rating/language chips. A static source ignores the query and returns the full set; the client filters.

GET/chapter

Backs the Home "Latest updates" row. Collection of recent chapter entities (same shape as a feed entry) across every title, ordered by readableAt desc.

Response (abbreviated)

{
  "result": "ok",
  "response": "collection",
  "data": [
    { "id": "ch-30-a", "type": "chapter",
      "attributes": { "chapter": "1", "readableAt": "2026-10-26T20:59:00+00:00",
                      "translatedLanguage": "en", "pages": 3, "...": "..." },
      "relationships": [ { "id": "demo-30", "type": "manga" }, { "...": "..." } ] },
    { "id": "ch-29-a", "...": "..." }
  ],
  "limit": 15, "offset": 0, "total": 15
}

The relationships[] entry of type == "manga" is used to look up and show the series title / cover beside the chapter row. The demo caps this collection at 15 entries; a dynamic backend should return the latest N (configurable).

GET/manga/tag

The master tag list. Backs the Tag chip picker on Search. Shape mirrors the inline tags[] on a manga entity.

Response

{
  "result": "ok",
  "response": "collection",
  "data": [
    { "id": "11111111-1111-4111-8111-111111111111", "type": "tag",
      "attributes": { "name": {"en": "Action"}, "description": {},
                      "group": "genre", "version": 1 },
      "relationships": [] },
    { "id": "22222222-...", "...": "..." }
  ],
  "limit": 10, "offset": 0, "total": 10
}

IDs should be stable across deployments — users and the local DB reference them. group is a free-form string; the client groups chips by its value.

POST/report

Health reporting sink for off-host image downloads. ReaDex POSTs a small JSON body after each page/cover download that targeted a host other than the API host, so a dynamic backend running an image-fan-out network can route around slow mirrors. The call is fire-and-forget with a short timeout; if the sink is absent, 404/5xx responses are tolerated and the client stops retrying for a while.

Request body

{
  "url": "https://cdn.example.com/data/ch-01-a/page-1.png",
  "success": true,
  "cached": false,
  "bytes": 42318,
  "duration": 184
}

A static source should either omit the key entirely (and let the fallback {base}/report 404) or set report_url to a known-good no-op.

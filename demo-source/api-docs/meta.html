/_meta.json

The one-shot discovery document. Served from the base URL, read once at setup, cached per source.

Fetch

After the user types a base URL at Setup and it passes the health check, ReaDex sends:

GET {baseUrl}/_meta.json

If the file is absent (404), the source is still valid; the client falls back to the defaults below for every key. If the file is present, each key is read and persisted on the local sources row; non-string values and unknown keys are ignored.

Full example

{
  "covers_url":    "https://lajennylove.github.io/readex/covers",
  "report_url":    "https://lajennylove.github.io/readex/report",
  "status_family": "lajennylove.github.io",
  "static_json":   true
}

Keys

KeyTypeDefaultEffect
covers_url string (URL) {baseUrl}/covers Base for the cover-thumbnail URL template (covers.html). Set this when your image CDN is on a different host from your API.
report_url string (URL) {baseUrl}/report Endpoint the client POSTs health reports to after off-host image downloads. Can be a no-op; failures are swallowed.
status_family string "" (none) Opaque label grouping this source with related ones in the local status cache (used to deduplicate error banners when a user has several sources under the same operator). Not shown to the user.
static_json boolean false When true, every API GET has .json appended to the path before the query string. Lets a plain static file tree (GitHub Pages, S3, Netlify) serve the endpoint contract without routing. Query parameters are still sent and are expected to be ignored.

When defaults are enough

A dynamic source that lives at one host, routes all paths, and serves cover images under /covers does not need to publish _meta.json at all. Everything is reachable at the fallback locations.

When to publish it

  • Your API host and your image host are different (covers_url).
  • You want to collect health telemetry on a dedicated endpoint (report_url).
  • You serve from a static file host and need the .json suffix behaviour (static_json).
  • You run several sibling sources and want them clustered in the local status cache (status_family).

Cache behaviour

The response is read once at setup and saved to the local DB. Changing _meta.json on the server after a user has configured the source does not re-fetch the file; the user would need to re-run Setup or clear source metadata from Settings for the new values to take effect.

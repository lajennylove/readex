Overview

What a ReaDex source is, how its three roles tie together, and the smallest version that lights up the Home screen.

Three roles behind one base URL

The user types a single URL at Setup (the base URL). From that one URL, ReaDex expects to reach three logical surfaces:

  1. API — JSON responses for the catalog, title detail, chapter feed and page lists. Rooted at {base}/api/ by default.
  2. Covers CDN — static image files for title cover thumbnails. Rooted at {base}/covers/ by default.
  3. Optional seasonal — a single JSON file naming the IDs that should populate the Home "This season" row. The user pastes this URL separately in Settings; no default location.

All three can live on the same host (the demo serves API + covers from the same GitHub Pages origin) or be split across hosts via /_meta.json.

Discovery via /_meta.json

At setup time, after the base URL passes a health check, ReaDex optionally GETs {base}/_meta.json. If present, the keys inside override the default {base}/covers and {base}/report locations and declare client-side behaviours (such as static_json, which appends .json to every API path so a plain file tree can serve the contract). See meta.html.

A source that doesn't publish _meta.json is still valid — the app falls back to {base}/covers and {base}/report, with static_json off.

Response envelope

Every API response is a JSON object with this shape:

{
  "result": "ok",
  "response": "collection",   // or "entity" for a single item
  "data": [ ... ],            // array for collection, object for entity
  "limit": 30, "offset": 0, "total": 30   // collections only
}

The app treats result and response as advisory — it reads from data directly. Pagination counters are ignored for the static demo (which returns every row in one shot); a real backend should return accurate limit/offset/total.

Content-rating & language filtering

ReaDex passes query parameters like contentRating[]=safe&contentRating[]=suggestive and availableTranslatedLanguage[]=en. A dynamic backend should honour them. A static source cannot — it returns the full catalog and the client filters locally on attributes.contentRating and attributes.availableTranslatedLanguages.

Error behaviour

HTTP 404 and 405 on any endpoint are tolerated: the affected row simply hides. 5xx raises an error dialog on the matching screen. Non-HTTPS base URLs are rejected at setup.

Minimum viable source

The smallest working source only needs the files below. Serve them as static JSON, set static_json: true in _meta.json, and the Home screen will populate.

  • /_meta.json — one object (see meta.html).
  • /api/manga/_catalog.json — a collection of every title. Backs the Home "Browse" row.
  • /api/manga/{id}.json — one file per title, entity response.
  • /api/manga/{id}/feed.json — one file per title, collection of its chapters.
  • /api/at-home/server/{chapterId}.json — one file per chapter, naming its page images.
  • /covers/{mangaId}/cover.256.jpg — one JPEG per title. Skippable if the manga JSON embeds absolute cover URLs under the cover_art relationship's fileName.

Everything else — chapter.json, manga.json, tag.json, seasonal — is optional. Missing files 404 and the matching row hides.
